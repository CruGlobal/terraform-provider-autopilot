# AGENTS.md

Guidance for coding agents (and people) working in this repository.

## Overview

Terraform provider for AutoPilot's admin API, built on
terraform-plugin-framework (not SDKv2) and published to the Terraform Registry
as `CruGlobal/autopilot`. AutoPilot runs AI agents on work that senders such
as issue trackers send it, and opens pull requests a person reviews. The
provider manages two records: `autopilot_sender` and `autopilot_app`.

Conventional Commits drive release-please (CHANGELOG.md and version bumps),
so commit messages and PR titles matter. The `Validate PR title` check
enforces the allowed types (see `.github/workflows/semantic-pr.yml`).

## This repository is public

Commits, code comments, docs, examples and test fixtures must not carry:

- internal hostnames (use `https://autopilot.example.com` and `example.com`
  names), account ids, project or user ids, work-item keys, chat channels,
  or people's names and email addresses;
- secrets of any kind. Tests make random secrets at run time
  (`randSecret`); never commit a fixed one.

Write docs and comments in plain words, without em dashes.

## Common commands

The project uses [Task](https://taskfile.dev) (`Taskfile.yaml`):

- `task build`: `go build`
- `task vet`, `task lint`: `go vet ./...`, `golangci-lint run` (v2, config in
  `.golangci.yml`; CI pins the version in `ci.yml`)
- `task test`: unit tests against the in-process fake (`go test ./...`);
  needs the terraform CLI, 1.11 or later, on `PATH`
- `task testacc`: the same tests against a live AutoPilot (`TF_ACC=1`,
  `AUTOPILOT_ENDPOINT`, `AUTOPILOT_TOKEN`, optional `AUTOPILOT_ACC_REPOS`)
- `task sweep`: removes the `tfacc-` apps and senders a failed live run left
  behind (the sweepers in `internal/provider/sweep_test.go`)
- `task generate`: regenerates `docs/` with tfplugindocs. CI fails when the
  result differs from what is committed, so run it after any schema,
  description or example change and commit the output.

Run a single test:

```sh
go test -count=1 -run TestSender_rotationByFingerprint ./internal/provider/
```

Tool versions are pinned in `.tool-versions` (asdf); CI's setup-go reads it.

## Layout

```
main.go                     providerserver entrypoint; version set by goreleaser
internal/client/            hand-written admin API client: retries, refusals, records
internal/autopilottest/     in-process fake of the admin API, used by every test
internal/provider/          provider, resources and their tests (one package)
examples/                   Terraform examples that tfplugindocs puts in docs/
docs/                       GENERATED by tfplugindocs; do not edit by hand
tools/                      pins tfplugindocs as a module dependency
```

## The contract

The provider codes to AutoPilot's admin API contract (`docs/admin-api.md` in
AutoPilot's own repository). When the contract changes, change all of these
together: the client (`internal/client`), the fake (`internal/autopilottest`,
which must refuse whatever the real API refuses), the resource, its tests,
the examples, and the generated docs. Things worth knowing:

- Records are keyed by name. A `POST` for a name that already holds the same
  fields answers `200` with the record, so creates are retried freely and no
  `Idempotency-Key` is sent. `client.Adopted` marks a `200` the provider's
  own lost send can't explain. `autopilot_app` refuses it and says to
  import; `autopilot_sender` warns, since its secrets matched too.
- Every `PATCH` and `DELETE` carries `If-Match: "<lock_version>"`. A stale
  update is reported, never retried over. A stale delete re-reads once.
- A change is safe to retry: AutoPilot answers a `PATCH` one version behind,
  whose body the record already holds, with `200`. So a change whose answer
  was lost is simply sent again. `patchRecord` keeps a fallback for an
  AutoPilot that answers such a repeat with `stale_object`: it reads the
  record and takes the change as its own only when the record is one version
  on and holds what it sent.
- The API refuses fields it doesn't know. Send only what is set
  (`SenderSpec` and `AppSpec`: a nil list is not sent, an empty one is sent
  as `[]`), so the provider keeps working against an AutoPilot that predates
  a newer optional field.
- Lists are sets in the schema; the client sends them sorted and without
  repeats, which is how the API keeps them. Values are kept as sent, and a
  `PATCH` replaces a list as sent, so a change of case alone is a change.
  Where a rule says "without regard to case" (repositories), that is how
  AutoPilot compares values and keeps them unique.
- A sender's secrets are write-only (`*_wo`). The plan compares
  `client.Fingerprint` of the configured secrets with the stored
  fingerprints; see the comment at the top of `sender_resource.go`.

## Tests

Every test body runs against the fake by default and against a live
AutoPilot under `TF_ACC`. Tests that need fault injection, writes from
outside Terraform, or the request log call `env.requireFake(t)`. Live tests
make records with random names (`randName`) and must clean up after
themselves; never write a test that needs a particular live record.
